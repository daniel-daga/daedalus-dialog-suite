## F11 — Error-position convention (parser + editor contract)

### Decision

**1-based rows and columns everywhere.** This matches `ErrorVisitor`
(`src/semantic/visitors/error-visitor.ts`), the human-readable error messages both
emitters already produce, and Monaco's 1-based marker coordinates.

### Current state (audited 2026-06-10)

| Producer | Position basis |
|---|---|
| `ErrorVisitor` → `semanticModel.errors[].position` | 1-based |
| `DaedalusParser.collectErrors` (`src/core/parser.js:232`) → `validate()` / `parse()` errors | 0-based (raw tree-sitter `startPosition`) |

| Consumer | Assumes | Correct today? |
|---|---|---|
| `SyntaxErrorsDisplay.tsx:52` — displays `position.row` raw (model errors) | 1-based | ✅ |
| `SourceCodeEditor.tsx:93-94` — Monaco markers do `row + 1` on `fileState.errors` (model errors, already 1-based) | 0-based | ❌ markers off by one **today** |
| `ValidationErrorDialog.tsx:110` — displays `row + 1` (ValidationService errors from `parse()`) | 0-based | ✅ |
| `useAutoSave.ts:100-104` — maps validation errors to `{message, line, column}` | 0-based | ❌ shape mismatch: `fileState.errors` is `ParseError[]` with a `position` field, so these errors never produce Monaco markers |

### Steps

1. **Parser test first** (`daedalus-parser/test/`): assert `validate()` on source with an
   error on line 3 returns `errors[0].position.row === 3` (fails today with `2`). Cover
   both the `ERROR`-node and `isMissing` branches.
2. **Fix `parser.js collectErrors`**: emit
   `position: { row: node.startPosition.row + 1, column: node.startPosition.column + 1 }`
   in both branches (build a new object; stop passing the tree-sitter `Point` through).
3. **`index.d.ts`**: document on `Position` that `row`/`column` are 1-based (comment; no
   shape change).
4. **Editor consumers** (same change set — this is one contract):
   - `SourceCodeEditor.tsx`: drop the `+1` on row/column (fixes the existing
     off-by-one for semantic-model errors; positions now map 1:1 to Monaco).
   - `ValidationErrorDialog.tsx`: drop the `+1`.
   - `useAutoSave.ts`: map validation errors to `{ message, position: e.position }` so
     they match `ParseError` and surface as Monaco markers.
   - `SyntaxErrorsDisplay.tsx`: no change.
5. **Editor test**: Jest test pinning the marker/display math (extract
   `updateMarkers`'s position mapping if needed to make it testable without Monaco).

### Verify

- `npm test`, `npm run lint`, `npm run typecheck` in `daedalus-parser/`
- `npm test`, `npm run typecheck:renderer` in `daedalus-dialog-editor/`
- Manual smoke: open a file with a syntax error; marker line, error-dialog line and
  syntax-error panel line all agree with the editor gutter.

## F9 — String escaping asymmetry

### Decision

**Daedalus has no string escape sequences.** ZenGin treats everything between the outer
quotes as raw text; an embedded `"` cannot be represented. Therefore the toolchain must
**never escape or unescape** string content. Strings roundtrip verbatim, and the
impossibility of embedded quotes is enforced at the editor input boundary.

### Current state

- Parse side is already raw: `normalizeArgumentText`
  (`src/semantic/parsers/argument-parsing.ts:20`) strips only the outer quotes.
- `Choice.generateCode` (`src/semantic/dialogActions.ts:60`) escapes `\` and `"` on
  emit — the only asymmetric emitter. Source text `"C:\path"` regenerates as
  `"C:\\path"`; a literal `\"` double-escapes on every roundtrip.
- `DialogLine.generateCode` quotes `this.id` (identifier-shaped, unaffected);
  `LogEntry.generateCode` quotes `this.text` raw (already symmetric).

### Steps

1. **Parser test first**: roundtrip test where a choice text contains a backslash, e.g.
   `Info_AddChoice (DIA_X, "Pfad C:\test", DIA_X_fn);` → regenerated byte-identical
   (fails today: emits `C:\\test`).
2. **Fix `Choice.generateCode`**: emit `this.text` verbatim inside quotes; delete the
   escape `replace` chain.
3. **Sweep for other escapers**: grep `replace(/\\\\/g` / `\\"` across
   `daedalus-parser/src/`; assert no emit or parse path escapes/unescapes string content
   (including the serialization/deserialization paths in `dialogActions.ts`).
4. **Editor input boundary**: user-entered text for Choice / LogEntry (and any other
   quoted-string field) must reject the `"` character, since it cannot be represented.
   - Jest test first: `ValidationService` flags a model whose choice/log-entry text
     contains `"` with a clear, actionable error (single boundary that covers all save
     paths, incl. auto-save).
   - Optionally surface the same rule inline in `ChoiceRenderer.tsx` (field-level error
     text) — UI nicety, not the safety boundary.
5. **Corpus validation**: run `npm run test:roundtrip-corpus` and confirm no corpus
   regressions (corpus files containing `\` in strings should now roundtrip cleanly —
   this fix can only remove diffs, not add them).
6. **Docs**: record the "no escape sequences" decision in
   `docs/reference/parser-roundtrip-scope.md`.

### Verify

- Parser: `npm test`, `npm run lint`, `npm run typecheck`, `npm run test:roundtrip-corpus` (root)
- Editor: `npm test` (ValidationService suite)

## F14 — Extend lint to TypeScript sources

Folded out of `daedalus-parser-stabilization.md` Phase 2 (lint recovery is done for JS;
this completes the scope). ~4.6k lines of TS in `daedalus-parser/src/` are currently
unlinted — including the files where F1–F3 lived.

### Steps

1. Add `typescript-eslint` (flat-config package) to `daedalus-parser` devDependencies.
2. Extend `eslint.config.js` with a block for `src/**/*.ts`:
   - `tseslint.configs.recommended` (non-type-checked to start; type-checked configs can
     follow later if signal warrants),
   - `no-unused-vars` off in favor of `@typescript-eslint/no-unused-vars` with the same
     `^_` ignore patterns as the JS block.
3. Update `package.json` `lint` / `lint:fix` scripts to include `src/**/*.ts`
   (keep `--max-warnings 0`).
4. Fix resulting violations. If `@typescript-eslint/no-explicit-any` produces a large,
   low-value backlog, disable that single rule with a TODO rather than churning the
   sources — the goal is real-bug rules (unused vars, dupe keys, unsafe patterns) being
   active, not an `any` crusade.
5. Update `daedalus-parser-stabilization.md` Phase 2 to note TS lint scope is complete
   (or delete the cross-reference in `parser-review-fixes.md` notes).

### Verify

- `npm run lint` green with TS files demonstrably in scope (introduce a deliberate
  unused variable in a TS file, confirm lint fails, revert).
- `npm test`, `npm run typecheck` still green.
